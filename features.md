# Feature Queue: Design Simplification (Clean Design)

Generated by NightPrep Agent on 2026-03-14

## Overview

This batch implements the design simplification recommendations from docs/CleanDesign.md, covering Phase 1 (Quick Wins) and Phase 2 (Moderate Effort) changes. The goal is to reduce visual clutter, eliminate redundant UI elements, remove dead code, and consolidate the tab architecture from 7 tabs to 5. These changes follow the app's core design principles: calm by default, dark is home, disappearing UI, contrast matters, and motion with purpose.

## Global Requirements

The following requirements apply to ALL features in this batch:

- **Translations**: Every user-facing string must use `String(localized:)` or `LocalizedStringKey` and be added to the existing `Localizable.xcstrings` file at `SoundScape/Resources/Localizable.xcstrings`. The source language is English.
- **Build Verification**: The project must build successfully after each feature: `cd SoundScape && xcodebuild -scheme SoundScape -destination 'platform=iOS Simulator,name=iPhone 16 Pro' build`
- **Dark Theme**: All modified views must continue to follow the app's existing dark theme patterns and styling.
- **No Regressions**: Existing functionality must continue to work. Sound playback, mixer, timer, saved mixes, and all audio features must be unaffected.
- **OLED Mode**: Any views that currently support OLED mode must continue to do so after changes.

## Features

### 1. Remove Favorites Tab and Consolidate to Chip Filter

The Favorites feature is currently accessible from three separate places: a dedicated Favorites section at the top of SoundsView, a "Favorites" chip in CategoryFilterView, and a dedicated Favorites tab. This creates redundant UI and duplicated code. Users should access their favorites through a single entry point.

**User Story:**
As a user, I want to access my favorited sounds from the Sounds tab using the "Favorites" chip filter so that the interface is simpler and I don't see the same content repeated in multiple places.

**Acceptance Criteria:**
- The dedicated Favorites tab is removed from the tab bar
- The always-visible Favorites section at the top of SoundsView is removed
- The "Favorites" chip in CategoryFilterView continues to work and shows all favorited sounds when selected
- Favoriting and unfavoriting sounds continues to work everywhere (heart icon on sound cards)
- The tab count is reduced by one (from the current count)
- No favorites data is lost; the FavoritesService continues to persist favorites

**Priority:** 1
**Dependencies:** None

### 2. Simplify Sleep Buddy Settings Row

The Sleep Buddy feature is unreleased ("Coming Soon"), but its Settings row has five visual state changes on tap (icon color, text, arrow icon, arrow color, disabled state). An unreleased feature should not have complex interactive behavior that confuses users.

**User Story:**
As a user, I want the Settings screen to clearly show which features are available now and which are coming soon, without confusing interactive behavior on unreleased features.

**Acceptance Criteria:**
- The Sleep Buddy row in Settings is displayed as a static, non-interactive card
- The row shows a "Coming Soon" badge in a subtle style (e.g., secondary text color)
- Tapping the row does nothing (no color changes, no state transitions, no navigation)
- The row appears visually distinct from active settings (e.g., slightly dimmed or grayed out)
- All other Settings rows continue to work as before

**Priority:** 1
**Dependencies:** None

### 3. Remove Non-Functional Buttons

Two buttons in the app are non-functional dead code: the Share button in MixDetailView (Discover tab) and the Play button in RecommendationsView (Insights tab). Dead UI elements erode user trust when tapped and nothing happens.

**User Story:**
As a user, I expect every button I see to actually do something. Removing buttons that don't work makes the app feel more polished and trustworthy.

**Acceptance Criteria:**
- The Share button is removed from MixDetailView
- The Play button is removed from RecommendationsView
- The layout of both views adjusts cleanly after the buttons are removed (no empty space or broken alignment)
- All other buttons in these views continue to work correctly

**Priority:** 1
**Dependencies:** None

### 4. Simplify Paywall Pricing Card Selection

When users select between yearly and monthly plans on the paywall, four visual indicators change simultaneously (background color, border stroke, selection circle, disabled opacity). This is visually noisy and redundant. Two indicators are sufficient to communicate selection state.

**User Story:**
As a user, I want the pricing plan selection to feel clean and clear, with obvious visual feedback showing which plan I've selected without overwhelming visual changes.

**Acceptance Criteria:**
- Selected pricing card uses only two visual indicators: background color fill and a checkmark circle
- The border stroke change on selection is removed
- The disabled opacity change on the unselected card is removed
- The "Save X%" badge on the yearly plan is preserved (it drives conversions)
- The selection still feels responsive and clear to the user
- Both OnboardingPaywallView and any other paywall presentation use the simplified selection

**Priority:** 1
**Dependencies:** None

### 5. Fix ParticleLayer and FlowLayer Timer Memory Leaks

ParticleLayer and FlowLayer use `Timer.scheduledTimer()` that is never invalidated when the view is removed. This causes memory leaks as timers continue firing after the user navigates away. This is a critical performance issue.

**User Story:**
As a user, I want the app to run smoothly without consuming unnecessary memory or battery, especially during long overnight sleep sessions.

**Acceptance Criteria:**
- ParticleLayer's timer is properly invalidated when the view disappears (in `.onDisappear` or equivalent)
- FlowLayer's timer is properly invalidated when the view disappears
- No timer references are retained after the view is removed from the hierarchy
- Alternatively, if appropriate, replace `Timer.scheduledTimer()` with `TimelineView` which automatically handles lifecycle
- The visual animations continue to work correctly when the views are visible
- No visual changes to the particle or flow animations

**Priority:** 1
**Dependencies:** None

### 6. Consolidate Tabs from 7 to 5

The app currently has 7 tabs, exceeding Apple's Human Interface Guidelines recommendation of 3-5 tabs. This causes small touch targets, cognitive overload, and features that users never discover. Wind Down and Sleep Recording are both nighttime activities that belong together. Discover and Adaptive are both "explore new soundscapes" experiences that belong together.

**User Story:**
As a user, I want fewer tabs so I can easily find features without being overwhelmed by choices. Grouping related features together makes the app feel more focused and intentional.

**Acceptance Criteria:**
- Tab bar shows 5 tabs: Sounds, Binaural, Sleep, Explore, Insights
- The "Sleep" tab contains Wind Down content and Sleep Recording as sections or segments (e.g., a segmented control or toggle at the top: "Wind Down" | "Sleep Rec")
- The "Explore" tab contains Discover community mixes and Adaptive sessions as sections or segments (e.g., "Discover" | "Adaptive")
- All existing functionality from the merged tabs remains fully accessible
- The tab bar icons and labels are clear and appropriate for the merged tabs
- Navigation within each merged tab is smooth and intuitive
- The Now Playing bar continues to work correctly across all tabs

**Priority:** 2
**Dependencies:** Feature 1

### 7. Simplify WindDown Cards

WindDown is the most cluttered screen in the app with 30+ interactive elements, content duplicated across 4 different layouts, and 6 category colors competing for attention. Cards show too much information (badge, title, description, narrator, duration, progress, play button) when most of it belongs in the player, not on browse cards.

**User Story:**
As a user browsing sleep content at bedtime, I want a calm, simple browsing experience with clean cards that show just enough information to choose content, without being overwhelmed by details I can see after I start playing.

**Acceptance Criteria:**
- All content cards use a single unified card template (with size variations for featured vs. regular)
- Decorative 80pt icons are removed from cards
- Narrator name is hidden on cards (shown only in the player when content is playing)
- Progress bars are removed from cards (shown only in the player)
- Each category section shows a maximum of 3 items with a "See All" link to view the rest
- The "FEATURED" badge is removed (the section header "Featured" is sufficient)
- The overall visual element count on the WindDown screen is reduced by approximately 40-50%
- Content still plays correctly when a card is tapped
- The player view continues to show full details (narrator, progress, duration)

**Priority:** 2
**Dependencies:** None

### 8. Create AppTheme and Centralize Design Tokens

Colors are hardcoded throughout the codebase: `.purple` appears 20+ times, OLED opacity values (0.1, 0.2, 0.3) are hardcoded in 4 modifiers, category colors are re-derived in views instead of using the single source in Sound.swift, and the ASMR purple is defined with raw RGB values in multiple files. This makes theming inconsistent and changes error-prone.

**User Story:**
As a user, I want the app to look visually consistent across all screens, with colors and styles that feel cohesive and intentional rather than slightly different from screen to screen.

**Acceptance Criteria:**
- An AppTheme struct (or similar) is created that centralizes all design tokens: accent colors, category colors, OLED opacity values, standard corner radii, spacing values
- All hardcoded `.purple` references throughout the codebase reference the centralized theme color instead
- OLED opacity values use named constants (e.g., `AppTheme.cardOpacity`, `AppTheme.glowIntensity`) instead of magic numbers
- Category colors in views reference `Sound.category.color` (the existing single source) instead of re-deriving colors
- The ASMR purple `Color(red: 0.8, green: 0.6, blue: 1.0)` is defined once in the theme and referenced everywhere
- The visual appearance of the app is unchanged (same colors, same styles) -- this is a code organization improvement
- The AppTheme is accessible throughout the app without additional environment injection

**Priority:** 2
**Dependencies:** None

### 9. Extract Mixer Limit and Paywall Logic to Services

The `wouldExceedMixerLimit()` check is duplicated inline in SoundsView and FavoritesView. The paywall trigger flow is duplicated across SoundsView, FavoritesView, DiscoverView, AdaptiveView, and InsightsView. The save mix conversion logic is duplicated in DiscoverView. This duplication means bug fixes and behavior changes must be applied in multiple places.

**User Story:**
As a user, I want the premium upgrade experience to behave consistently everywhere in the app, so I'm never confused by different behaviors when I hit a limit in different places.

**Acceptance Criteria:**
- The `wouldExceedMixerLimit()` logic exists in one place (PremiumManager or equivalent service) and is called from SoundsView and FavoritesView (and any other view that needs it)
- The paywall trigger flow follows one code path regardless of which screen triggers it
- The save mix conversion logic in DiscoverView is moved to SavedMixesService
- Category color derivation in views uses `Sound.category.color` instead of re-deriving
- All premium limit checks behave identically across every screen
- No user-facing behavior changes -- this is a consistency and maintainability improvement

**Priority:** 2
**Dependencies:** None

### 10. Consolidate SoundsView Toolbar

The SoundsView toolbar currently has 3 trailing buttons (mixer, timer, saved mixes) plus a conditional ASMR info button on the leading side. Combined with 8+ category filter chips below, the top of the screen is dense with competing actions. This violates the "disappearing UI" design principle.

**User Story:**
As a user, I want the sound browsing experience to feel spacious and calm, with tools available when I need them but not cluttering the screen when I'm just browsing.

**Acceptance Criteria:**
- The 3 trailing toolbar buttons (mixer, timer, saved mixes) are consolidated into a single "Tools" menu button
- Tapping the Tools button reveals a menu with options: Mixer, Timer, Saved Mixes
- Each menu option opens the same sheet modal as the current toolbar buttons
- The ASMR info button is moved to appear as a section header element when the ASMR category is selected (not in the toolbar)
- The toolbar feels cleaner with fewer competing icons
- All sheet modals (mixer, timer, saved mixes) continue to function identically

**Priority:** 2
**Dependencies:** None
