## Architecture Overview
Pattern: Clean Architecture (Domain → Data → Presentation), service-oriented Data layer

The domain layer holds only pure value types (structs/enums) and protocol contracts with zero framework coupling. The data layer implements those protocols as `@Observable @MainActor final class` services that are instantiated once in `SoundScapeApp`, wired via post-init setter injection, and propagated downward through the SwiftUI environment. Presentation views are stateless shells that read reactive service state and dispatch closures back to services — there are no ViewModels except `SoundsViewModel`. An App Group (`group.com.StudioNext.SoundScape`) bridges the main target to a WidgetKit/ControlWidget extension; App Intents use an independent `ServiceContainer` singleton and do not share audio engine state with the live app.

## Cross-Cutting Concerns
- Error Handling: No centralized error handling; services use `try?` for file I/O; async failures silently ignored in most views; `SubscriptionService` purchase errors are captured and exposed as `@Published`-style observable properties
- State Management: `@Observable` + `@Environment` throughout; mutations are synchronous and immediately written to persistence (write-through, no dirty tracking); no Combine publishers or async streams except `Transaction.updates` in `SubscriptionService`
- Premium Gating: `PremiumManager.isPremiumRequired(for: .featureKey)` → `PaywallService.triggerPaywall(placement:onUnlock:)` with deferred unlock closure; `OnboardingPaywallView` is the single shared paywall UI reused across all gating points
- Audio Session: All audio managed by `AudioEngine` (`AVAudioSession`); `BinauralBeatEngine` runs a separate `AVAudioEngine` pipeline; both must coordinate to avoid session conflicts
- OLED Mode: `AppearanceService.isOLEDModeEnabled` checked in all background/card modifiers via `OLEDBackgroundModifier` extensions; set on `UITabBarAppearance` imperatively
- Widget Sync: `AudioEngine` and `SleepTimerService` write `WidgetSharedState` to App Group `UserDefaults` after each state change; `WidgetKit.reloadTimelines()` called after writes
- Analytics: `AnalyticsService` wraps Firebase with typed `Event` enum; called from services (not views) after state changes; must call `.configure()` at app launch before any events fire
- Testing: No mocks — real services instantiated directly; persistence state cleared in `setUp`/`tearDown`

## Developer Conventions
- File Naming: `[Feature]View.swift`, `[Feature]RowView.swift`, `[Feature]CardView.swift`; services as `[Domain][Role].swift` (e.g., `AlarmNotificationSoundManager`, `LocalSoundDataSource`)
- Module Organization: `Domain/Entities/` one-entity-per-file with related nested types; `Data/Services/` one-service-per-file; `Presentation/[Feature]/Views/` + optional `Components/` and `ViewModels/`
- Service Injection: Services always via `@Environment(ServiceName.self)` — never passed as init parameters to views; sub-views receive user-action callbacks as `() -> Void` closures
- Bindable Pattern: `@Bindable var x = serviceFromEnv` to get a two-way binding reference from an `@Environment` `@Observable` object for `Picker`/`Slider`
- Cross-Service Deps: Post-init setter injection (`setInsightsService(_:)`) to avoid circular init-time dependencies; wired in `SoundScapeApp.onAppear`
- Preview Blocks: Every view has `#Preview` with real services injected; dark color scheme set as default
- Entity IDs: String for catalog sounds (`"morning_birds"`), UUID for user-created records (`Alarm`, `SavedMix`, `SleepSession`)
- Codable Discipline: Persisted entities conform to `Codable`; ephemeral runtime entities (e.g., `SleepTimerPreset`) do not

### Common Pitfalls
- Adding a new sound ID in `LocalSoundDataSource` also requires updating `AdaptiveMode.phases` hardcoded string IDs if any adaptive mode references it
- Adding a file to Xcode requires 4 pbxproj entries (not 1): PBXBuildFile, PBXFileReference, group children array, and PBXSourcesBuildPhase (or PBXResourcesBuildPhase for assets)
- `ServiceContainer` (App Intents) creates its own `AudioEngine` — intent-triggered playback does NOT affect the main app's audio session
- `BinauralBeatEngine` settings (frequency, tone type) cannot be changed while playing — call `stop()` first, update, then `start()`
- `AudioEngine` fade-out uses async dispatch chains — stopping mid-fade can cause a brief volume reset; see `SavedMixesView` 400ms delay pattern as the workaround
- `WidgetSharedState` is a value type; load the full struct, modify, re-save — there is no partial update
- `InsightsService.calculateQuality()` is non-deterministic (`Int.random`); tests verify ranges only
- `SleepTimerPreset` uses `let id = UUID()` as an inline initializer — new UUID on every struct creation, not suitable for equality checks
- SourceKit "Cannot find type" diagnostics when editing outside Xcode are false positives — the project builds correctly in Xcode
- `WaveLayer`/`FlowLayer` `Timer.scheduledTimer` loops are never cancelled on `.onDisappear` — avoid adding more of these without cleanup
